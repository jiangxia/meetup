# AI酒馆项目 - 前后端分离开发指南

## 🎯 项目概述
AI酒馆是基于PromptX协议的多Agent演示系统，采用前后端分离架构，展示AI的记忆能力和角色概念。

## 🔄 前后端分工说明

### 前端职责 (Frontend_Tasks)
- **UI/UX设计和实现**: 所有用户界面组件
- **用户交互逻辑**: 点击、输入、动画等交互
- **状态管理**: 前端状态、本地缓存、Loading状态
- **API调用**: 与后端API的通信接口
- **数据展示**: 将后端数据格式化展示给用户

### 后端职责 (Backend_Tasks)
- **服务器架构**: Express服务器、中间件配置
- **API接口实现**: RESTful API、数据验证、错误处理
- **AI服务集成**: LLM API调用、LangChain框架
- **PromptX集成**: MCP工具调用、记忆系统
- **业务逻辑处理**: 消息处理、会话管理、算法实现

### 全栈协作 (Fullstack_Tasks)
- **接口对接**: 前后端API协议制定和联调
- **完整功能演示**: 需要前后端配合的核心功能
- **端到端测试**: 完整用户流程测试
- **集成调试**: 解决前后端集成问题

## ⚡ 开发优先级和依赖关系

### Phase 1: 基础设施搭建 (Day 1 上午)
**并行开发**:
- **前端**: Epic0.1 前端项目搭建 + Epic0.3 UI基础组件
- **后端**: Epic0.1 Node服务器搭建 + Epic0.2 API路由设计

**依赖关系**: 无依赖，可并行开发

### Phase 2: 核心功能实现 (Day 1 下午)
**串行开发**:
1. **前端**: Epic1.1 角色选择UI (依赖前端基础设施)
2. **前端**: Epic2.1 对话界面UI (依赖角色选择)
3. **后端**: Epic2.2 LLM API集成 (依赖后端基础设施)

**协作点**: API接口格式协商

### Phase 3: 消息系统集成 (Day 1 晚上)
**并行开发**:
- **前端**: Epic2.3 前端消息管理
- **后端**: Epic2.3 后端消息处理

**协作**: 消息状态同步、错误处理协议

### Phase 4: PromptX记忆演示 (Day 2 上午)
**串行开发**:
1. **后端**: Epic3.1 PromptX集成
2. **全栈**: Epic3.2 前后端记忆演示 (重点协作)

### Phase 5: 界面优化和角色切换 (Day 2 下午)
**并行开发**:
- **前端**: 界面美化和动画优化
- **后端**: 角色切换逻辑优化

### Phase 6: 集成测试和优化 (Day 2 晚上)
**全栈协作**:
- API接口联调
- 端到端测试
- 演示脚本准备

## 🚨 关键风险控制

### 前端风险
- **浏览器兼容性**: 优先支持Chrome，准备降级方案
- **网络请求失败**: 完善错误处理，支持重试
- **UI响应速度**: 优化动画，使用CSS硬件加速

### 后端风险
- **LLM API限流**: 准备多密钥轮换，设置合理重试
- **PromptX工具故障**: 准备Mock数据降级方案
- **服务器稳定性**: 完善错误处理，监控资源使用

### 协作风险
- **接口变更**: 建立API版本控制，及时同步
- **数据格式不一致**: 制定详细的接口文档
- **开发进度不同步**: 定期同步，优先完成核心功能

## 📞 协作沟通机制

### 日常沟通
- **每4小时同步一次**: 进度汇报，问题讨论
- **接口变更立即通知**: API修改必须双方确认
- **问题记录和解决**: 使用GitHub Issues跟踪

### 紧急情况处理
- **技术阻塞**: 立即寻求帮助，准备备选方案
- **进度延误**: 及时调整优先级，砍掉非核心功能
- **集成问题**: 优先解决，必要时简化实现
